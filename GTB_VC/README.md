# GreenTea Bot v3.2

Локальный инженерный Telegram-бот на базе Ollama и локальной языковой модели.

Бот рассчитан на работу на слабом железе, использует минимальный внешний каркас, сам создаёт нужные файлы при первом запуске и держит модель в памяти, чтобы первый пользовательский запрос не был медленным.

Развито и добавлено:

- параметр `thinking` в `settings.toml`;
- два стандартных промпта:
  - `GreenTea_v4_L` — полный промпт;
  - `GreenTea_v4_S` — компактный промпт для небольших моделей;
- улучшенную проверку прокси;
- более надёжный watchdog подключения;
- автоматическую миграцию старого промпта `GreenTea_v4` в `GreenTea_v4_L`.

---

## Особенности

### Монолитный запуск

При первом старте бот сам создаёт:

- `settings.toml`;
- `prompts/GreenTea_v4_L.txt`;
- `prompts/GreenTea_v4_S.txt`;
- папку `logs/`.

Если уже есть старый файл:

```text
prompts/GreenTea_v4.txt
```

и файла `GreenTea_v4_L.txt` ещё нет, бот постарается переименовать старый промпт в:

```text
prompts/GreenTea_v4_L.txt
```

### Два стандартных промпта

В комплекте идут два промпта:

| Промпт | Назначение |
|---|---|
| `GreenTea_v4_L` | Полный исходный промпт. Подходит для моделей побольше и для максимального качества поведения. |
| `GreenTea_v4_S` | Компактный промпт. Подходит для маленьких моделей, слабых машин и ограниченного контекста. |

Оба промпта следуют одной и той же логике поведения, но `GreenTea_v4_S` заметно короче.

### Параметр thinking

В секции `[ollama]` теперь есть параметр:

```toml
thinking = false
```

Если включить:

```toml
thinking = true
```

бот будет пытаться передавать в Ollama параметр `think`, если конкретная модель и клиент это поддерживают.

Если модель или библиотека не поддерживают `think`, бот автоматически откатится на обычный запрос без `think`.

Важно:

- по умолчанию `thinking = false`, потому что бот ориентирован на слабое железо;
- служебный thinking-текст не отправляется пользователю;
- если модель вернула thinking-часть, бот только залогирует её наличие и объём.

### Прогрев модели

При старте бот:

1. проверяет доступность Ollama;
2. при необходимости пробует запустить `ollama serve`;
3. прогревает модель коротким запросом;
4. держит модель в памяти через `keep_alive`.

Это сделано, чтобы первый пользовательский ответ не начинался с долгой загрузки модели.

### Улучшенная проверка прокси

В новой версии проверка прокси стала строже.

Раньше проблема могла выглядеть так:

- бот успешно подключался через прокси;
- прокси формально поднимал соединение;
- но фактически Telegram API не отвечал;
- бот мог стоять молча.

Теперь:

- перед запуском прокси проверяется реальным HTTP-запросом через прокси;
- если токен уже известен, выполняется запрос к Telegram API `/getMe`;
- проверяется не только статус, но и то, что ответ похож на JSON Telegram;
- префлайт-проверка может делать несколько попыток;
- watchdog периодически делает отдельную сырую HTTP-проверку прокси;
- опционально можно включить принудительную ротацию прокси по времени жизни.

### Админ-панель

В личных сообщениях владельцу бота доступны команды:

- `/status`;
- `/history`;
- `/clear`;
- `/set`;
- `/get`;
- `/reset`;
- `/panel`;
- `/help`.

### Логи

Бот пишет логи в консоль и, если включено, в файлы внутри папки `logs/`.

## Требования

- Python 3.11+;
- Ollama;
- заранее скачанная модель в Ollama;
- желательно локальная машина с достаточным объёмом ОЗУ для выбранной модели.

## Установка зависимостей

```bash
python -m pip install --upgrade pip
pip install "python-telegram-bot>=20" ollama "httpx[socks]"
```

Если прокси не используются, можно установить обычный `httpx`:

```bash
pip install "python-telegram-bot>=20" ollama httpx
```

Но для `socks5`-прокси рекомендуется именно вариант с `httpx[socks]`.

## Установка и подготовка Ollama

Установите Ollama и скачайте модель, например:

```bash
ollama pull qwen2.5-coder:7b-instruct-q4_K_M
```

Проверка:

```bash
ollama list
```

Если вы используете десктопную версию Ollama, сервис обычно уже запущен.

Если используете консольный вариант, сервер можно запустить так:

```bash
ollama serve
```

Бот при старте сам проверит доступность:

```text
http://localhost:11434
```

и при необходимости попробует запустить `ollama serve`.

## Подготовка бота в Telegram

1. Создайте бота через `@BotFather`.
2. Получите токен.
3. Узнайте нужный `chat_id`.

Для работы в группе желательно:

- либо добавить бота администратором;
- либо отключить ему privacy mode через BotFather.

Для отключения privacy mode:

```text
/setprivacy
```

далее:

1. выбрать бота;
2. выбрать `Disable`.

Иначе бот может не видеть обычные сообщения группы, а только команды, ответы и упоминания.

## Первый запуск

Запустите скрипт:

```bash
python GTB_VC.py
```

Если файла `settings.toml` ещё нет, бот:

1. создаст конфигурацию по умолчанию;
2. создаст стандартные промпты:
   - `prompts/GreenTea_v4_L.txt`;
   - `prompts/GreenTea_v4_S.txt`;
3. попросит заполнить настройки и завершится.

После этого отредактируйте `settings.toml` и запустите бота снова.

## Файл токена

Токен можно хранить двумя способами.

### 1. В `settings.toml`

```toml
[bot]
token = "ВАШ_ТОКЕН"
```

### 2. В отдельном файле `key`

Если в настройках:

```toml
[bot]
token = ""
```

бот прочитает токен из файла `key` рядом со скриптом.

Файл `key` должен содержать только сам токен.

Не коммитьте `key` или заполненный `settings.toml` с токеном в git.

## Основные настройки: `settings.toml`

При первом запуске создаётся полный шаблон. Ниже описаны основные секции.

## Секция `[bot]`

```toml
[bot]
token = ""
chat_id = -1001234567890
username = "MyBot"
owner_id = 123456789
random_reply_chance = 0.05
proxy = ""
```

| Параметр | Описание |
|---|---|
| `token` | Токен бота. Если пустой, берётся из файла `key`. |
| `chat_id` | ID целевого чата, где бот будет отвечать. Для групп обычно отрицательный. |
| `username` | Имя бота без `@`. Используется для распознавания упоминаний. |
| `owner_id` | Ваш личный Telegram ID. Только он получает служебные сообщения и имеет доступ к админ-панели. |
| `random_reply_chance` | Шанс случайного ответа от `0.0` до `1.0`. |
| `proxy` | Режим прокси: `""` или `auto`, `direct` / `none`, либо конкретный `socks5://host:port`. |

## Секция `[ollama]`

```toml
[ollama]
model = "qwen2.5-coder:7b-instruct-q4_K_M"
prompt = "GreenTea_v4_L"
thinking = false
cpu_threads = 0
keep_alive = "6h"
warmup = true
```

| Параметр | Описание |
|---|---|
| `model` | Модель, установленная в Ollama. |
| `prompt` | Имя файла промпта без `.txt`. Например, `GreenTea_v4_L` или `GreenTea_v4_S`. Пустая строка отключает системный промпт. |
| `thinking` | Пытаться использовать режим `think`, если модель и клиент это поддерживают. |
| `cpu_threads` | Число потоков CPU. `0` — авто. |
| `keep_alive` | Сколько времени держать модель в памяти. Рекомендуется `"6h"`. |
| `warmup` | Прогревать ли модель при старте. |

## Промпты

По умолчанию бот использует:

```toml
[ollama]
prompt = "GreenTea_v4_L"
```

Стандартные файлы:

```text
prompts/GreenTea_v4_L.txt
prompts/GreenTea_v4_S.txt
```

### GreenTea_v4_L

Полный промпт.

Хорош для:

- моделей от 7B и выше;
- достаточного контекста;
- максимально полного следования правилам поведения;
- более стабильного стиля.

### GreenTea_v4_S

Компактный промпт.

Хорош для:

- маленьких моделей;
- слабого железа;
- небольшого контекста;
- ситуаций, когда полный промпт занимает слишком много токенов.

Он короче в разы, но сохраняет основной смысл:

- роль `GreenTeaBot`;
- стиль ответов;
- правила чтения входного JSON;
- правила обращения к анонимному админу;
- ограничения;
- запреты;
- форму отказа;
- служебную идентичность.

## Thinking

Параметр:

```toml
[ollama]
thinking = false
```

По умолчанию выключен.

Если включить:

```toml
[ollama]
thinking = true
```

бот будет пытаться использовать `think` в Ollama.

Поведение:

- если модель и клиент поддерживают `think`, запрос пойдёт с ним;
- если клиент не понимает параметр, бот автоматически повторит запрос без `think`;
- если Ollama вернёт ошибку, похожую на неподдерживаемый `think`, бот также откатится;
- служебный thinking-текст не отправляется пользователю;
- наличие и размер thinking-текста только логируются.

Для слабого железа рекомендуется оставить:

```toml
thinking = false
```

## Прогрев модели и `keep_alive`

Бот при старте:

1. проверяет доступность Ollama;
2. при необходимости пробует запустить `ollama serve`;
3. отправляет короткий пустой запрос для загрузки модели в память.

За это отвечают:

```toml
[ollama]
keep_alive = "6h"
warmup = true
```

Если прогрев не нужен:

```toml
[ollama]
warmup = false
```

Если модель большая или диск медленный, можно увеличить таймаут прогрева:

```toml
[advanced]
ollama_warmup_timeout = 1800.0
```

## Прокси

Бот умеет работать через прокси.

### Режимы

Автоматический режим:

```toml
[bot]
proxy = ""
```

или:

```toml
[bot]
proxy = "auto"
```

Бот будет автоматически подбирать `socks5`-прокси из источников, указанных в `[advanced]`.

Прямое подключение:

```toml
[bot]
proxy = "direct"
```

или:

```toml
[bot]
proxy = "none"
```

Конкретный ручной прокси:

```toml
[bot]
proxy = "socks5://127.0.0.1:1080"
```

---

## Как работает авто-режим

1. Бот загружает список прокси.
2. Нормализует их в `socks5h://`.
3. Делает предварительную проверку.
4. Использует рабочие.
5. Помечает сломанные.
6. При проблемах перезапускается и пробует другой прокси.

---

## Улучшенная проверка прокси

В новой версии префлайт-проверка стала строже.

Бот не просто проверяет, что прокси принимает соединения. Он делает реальный HTTP-запрос через прокси.

Если токен бота уже загружен, проверка идёт через:

```text
https://api.telegram.org/bot<token>/getMe
```

При этом проверяется:

- что запрос вообще прошёл;
- что ответ не является серверной ошибкой;
- что ответ похож на JSON Telegram.

Это помогает отфильтровать прокси, которые:

- принимают соединение;
- формально не падают;
- но не маршрутизируют трафик до Telegram;
- возвращают посторонние страницы;
- молча ничего не делают.

Если токен недоступен, используется запасной адрес:

```toml
proxy_preflight_url = "https://api.telegram.org/"
```

## Попытки префлайт-проверки

Параметры:

```toml
[advanced]
proxy_preflight_attempts = 2
proxy_preflight_pause = 1.0
```

Они задают:

- сколько раз проверять прокси перед запуском;
- какую паузу делать между попытками.

## Наблюдение за прокси во время работы

Во время работы бот запускает watchdog.

Он с интервалом:

```toml
proxy_health_interval = 25
```

проверяет:

1. Telegram API через `get_me`;
2. если включено, сырую HTTP-проверку прокси.

Сырая проверка выполняется отдельно от PTB-подключения и помогает заметить случаи, когда формально приложение ещё живо, но прокси уже не работает.

Параметры:

```toml
proxy_health_fails = 2
proxy_health_timeout = 10.0
proxy_health_raw_check = true
```

Если подряд набралось критическое число провалов, бот:

1. помечает прокси как нерабочий;
2. останавливает текущую сессию;
3. перезапускается с другим прокси.

---

## Принудительная ротация прокси по времени

Параметр:

```toml
proxy_max_lifetime = 0.0
```

По умолчанию выключено.

Если указать, например:

```toml
proxy_max_lifetime = 3600.0
```

бот будет принудительно ротировать прокси примерно через 3600 секунд работы.

Это может быть полезно, если прокси со временем деградирует, начинает зависать или молча терять трафик.

## Команды бота

Админ-команды доступны только владельцу бота, указанному в `owner_id`, и только в личных сообщениях.

| Команда | Назначение |
|---|---|
| `/ping` | Проверка живости бота. |
| `/panel` | Админ-панель. |
| `/help` | То же, что `/panel`. |
| `/status` | Состояние бота и текущие параметры. |
| `/history [N]` | Показать последние `N` сообщений истории. По умолчанию 10. |
| `/clear` | Очистить историю целевого чата. |
| `/get` | Показать текущие runtime-параметры генерации. |
| `/set <param> <value>` | Изменить параметр генерации до перезапуска. |
| `/reset` | Сбросить runtime-параметры к значениям из `settings.toml`. |

Примеры:

```text
/status
/history 20
/set temperature 0.2
/set max_tokens 512
/reset
```

Изменения через `/set` действуют только до перезапуска бота.

## История

История хранится в памяти процесса.

Особенности:

- после перезапуска история очищается;
- объём ограничен параметром:

```toml
[advanced]
max_history_size = 10
```

- пользовательские сообщения передаются модели в служебном JSON-формате;
- ответы бота хранятся как обычный текст.

## Анонимный админ чата

Если сообщение отправлено анонимным администратором Telegram, бот заменяет его на нейтральное имя.

По умолчанию:

```text
Админ
```

Это имя используется:

- в истории;
- в пользовательском JSON для модели;
- в системном промпте;
- в обращениях в ответах.

Если нужно другое имя:

```toml
[advanced]
anonymous_admin_name = "Admin"
```

Не рекомендуется подставлять туда реальные ники или личные имена.

## Обновление с прошлой версии

Краткий порядок обновления:

1. Сделайте резервную копию:
   - `settings.toml`;
   - папки `prompts/`.
2. Замените старый скрипт на новый.
3. Запустите бота.
4. Проверьте:
   - `prompt = "GreenTea_v4_L"` или `prompt = "GreenTea_v4_S"`;
   - `thinking = false`;
   - `keep_alive = "6h"`;
   - `warmup = true`.

Если у вас было:

```toml
prompt = "GreenTea_v4"
```

новый скрипт автоматически переключит промпт на:

```toml
prompt = "GreenTea_v4_L"
```

Если в вашем `settings.toml` нет новых параметров `[advanced]`, бот будет использовать значения по умолчанию.

## Диагностика и частые проблемы

### Бот создаёт `settings.toml` и завершается

Это нормальное поведение первого запуска.

Заполните обязательные поля и запустите снова.

---

### Ошибка токена

Проверьте:

```toml
[bot]
token = "..."
```

или файл `key`.

---

### Бот не отвечает в группе

Проверьте:

- правильный ли `chat_id`;
- правильный ли `username` бота без `@`;
- отключён ли privacy mode;
- добавлен ли бот в группу;
- имеет ли бот нужные права.

---

### Бот пишет, что занят

Это значит, что модель уже обрабатывает предыдущий запрос.

На слабом железе генерация может занимать много времени.

---

### Бот подключён, но молчит

В новой версии для этого улучшены проверки прокси и watchdog.

Проверьте в логах:

- строки `[PROXY]`;
- строки `[HEALTH]`;
- префлайт-проверки;
- сырые проверки прокси.

Можно попробовать:

```toml
[bot]
proxy = "direct"
```

чтобы исключить влияние прокси.

Если проблема только в прокси, используйте:

```toml
[advanced]
proxy_health_raw_check = true
proxy_health_fails = 1
proxy_max_lifetime = 1800.0
```

---

### Прокси проходит проверку, но работает нестабильно

Можно включить принудительную ротацию по времени:

```toml
[advanced]
proxy_max_lifetime = 1800.0
```

Или уменьшить число допустимых провалов:

```toml
[advanced]
proxy_health_fails = 1
```

---

### Ошибки Ollama

Проверьте:

```bash
ollama list
```

и:

```bash
ollama run qwen2.5-coder:7b-instruct-q4_K_M "test"
```

Также убедитесь, что сервер доступен:

```text
http://localhost:11434
```

---

### Прогрев модели не успевает завершиться

Увеличьте:

```toml
[advanced]
ollama_warmup_timeout = 1800.0
```

---

### Не хватает памяти

Попробуйте уменьшить:

```toml
[generation]
context_window = 4096
max_tokens = 512
```

Или используйте модель меньшего размера / квантования.

Также можно перейти на компактный промпт:

```toml
[ollama]
prompt = "GreenTea_v4_S"
```

---

### Thinking не работает

Если вы включили:

```toml
thinking = true
```

но ничего не изменилось или бот пишет, что модель не поддерживает такой параметр, бот автоматически продолжит работу без `think`.

Не все модели и не все версии клиентов поддерживают режим `think`.

Для слабого железа рекомендуется оставить:

```toml
thinking = false
```

## Безопасность

Не храните токен в публичном репозитории.

Если используете `key`, добавьте его в `.gitignore`.

Если храните токен в `settings.toml`, тоже не публикуйте этот файл.

Админ-команды доступны только `owner_id`.

Не указывайте реальные личные имена в `anonymous_admin_name`.

Пример `.gitignore`:

```gitignore
key
settings.toml
logs/
__pycache__/
```

Если вы хотите оставить шаблон настроек в репозитории, лучше хранить отдельный `settings.example.toml` без секретов.

## Назначение бота

Этот бот задуман как:

- локальный инженерный ассистент;
- компактный инструмент для коротких технических ответов;
- стабильный монолит без внешних баз данных;
- решение для работы на слабом железе;
- бот с сухим, точным и слегка циничным стилем ответов.

Он не рассчитан на:

- облачные интеграции;
- активный интернет-серфинг;
- работу с внешними файлами пользователя без явной реализации;
- длинные многостраничные ответы без необходимости.
